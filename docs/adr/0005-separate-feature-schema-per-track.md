# ADR 0005: One feature schema per track, not one shared canonical schema

- Status: Accepted
- Date: 2026-09-24
- Supersedes: the "one canonical CICFlowMeter schema" idea in PROJECT_PLAN.md v0.1

## Context

The first version of the plan assumed that because both datasets were produced with "CICFlowMeter", one canonical feature schema could serve both. That assumption was checked against the source code and is wrong.

Evidence (from `FlowFeature.java` in each repository, current master branches):

| | Upstream CICFlowMeter (ahlashkari) | Engelen et al. fork |
|---|---|---|
| Output columns (incl. Label) | 84 | 94 |
| Extra columns | none | Fwd RST Flags, Bwd RST Flags, Bwd Act Data Pkts, Bwd Seg Size Min, ICMP Code, ICMP Type, Fwd/Bwd/Total TCP Retrans. Count, Total Connection Flow Time |
| TCP flow end | first FIN | FIN exchanged both ways, or RST |
| Active/Idle features | encode an absolute timestamp (bug) | fixed |
| Fwd/Bwd PSH and URG flags | not incremented correctly (bug) | fixed |

So even columns with **identical names** do not mean the same thing:

- Flow boundaries differ (FIN/RST handling). Every per-flow statistic (duration, packet counts, bytes, IATs) is computed over a different set of packets.
- Active/Idle values in upstream output can contain time-of-capture information.
- PSH/URG flag columns in upstream output are unreliable.

CIC-Darknet2020 was generated by CIC in 2020 with an upstream version that is not documented in the sources checked. Corrected CIC-IDS2017 was generated with the Engelen fork.

## Decision

- Each track has its own schema file: `ml/config/schemas/track_a_cicids2017.yaml` and `ml/config/schemas/track_b_darknet2020.yaml`.
- Canonical snake_case names are shared where the source column name is the same, for readability only. **Sharing a name does not imply sharing a definition.** Each schema records its own extractor and notes semantic differences.
- Track B excludes the Active/Idle features (possible timestamp leakage) and the directional PSH/URG flag counts (unreliable), pending an EDA diagnostic.
- Track A excludes `ICMP Code`, `ICMP Type` and `Total Connection Flow Time` until their definitions and sentinel values are confirmed.
- A model's manifest pins the schema by id, version and SHA-256 of its content. A Track A model cannot be run with the Track B schema or vice versa (enforced by the inference gate).

## Consequences

- Adding a dataset means adding a schema and an adapter, not editing a shared one.
- No cross-dataset training or cross-dataset inference without a new ADR and a parity argument.
- Both schemas are drafts until the real CSV headers are checked (`cybersentinel-ml check-header`).

## Open verification items

- [VERIFY] The real CIC-Darknet2020 header. The Track B `raw_columns` is the current upstream header plus a second label column. The 2020 version may differ.
- [VERIFY] Whether Darknet2020 Active/Idle values look like timestamps (for example values near 1.5e15 microseconds would indicate epoch time).
- [VERIFY] Whether Darknet2020 PSH/URG flag columns are near-constant.
- [VERIFY] The exact commit of the Engelen fork that produced the chosen corrected release. The fork's master may contain columns added after WTMC 2021.
